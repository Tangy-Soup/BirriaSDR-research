# The MT7921 receiver: MT7961 and MT7972

The implemented board is the COMFAST dongle with USB ID `3574:6211`, an
MT7961 digital die and an MT7972 analog die. The backend is named `mt7921`
after the USB product family. Its enabled profile is receive chain 0,
channel 6 (nominal 2437 MHz), at 40 million complex samples per second.
Other boards, bands and rates need their own qualification.

The following sections follow one sample from the receiver to the application.
The [register reference](#register-reference) at the end distinguishes fields
used by the driver from observations whose meaning is still incomplete.

```mermaid
flowchart LR
    rf["RF/PHY chain 0"] --> icap["ICAP"]
    icap --> sram["Circular SRAM"]
    sram --> dma["Device DMA"]
    dma --> usb["USB"]
    usb --> host["Host I/Q"]
```

## Preparing the device

The host restores saved gain overrides, resets the Wi-Fi subsystem and prepares
its command transport. The ROM patch semaphore must report an unpatched device;
a software reset alone does not remove a previously loaded vendor patch.

Our original 1,120-byte program is loaded at `0x00915000` through the immutable
boot ROM. It calls the ROM PHY power-on helper at `0x00837142`, initializes its
DMA ring and waits for GO. A fresh nonce and response in the mailbox at
`0x02038360` establish that this run's program actually executed.

The host configures the stages below while capture is stopped, then queues
bulk reads before releasing GO. A STOP request ends descriptor submission,
drains the outstanding transfer, stops capture and publishes terminal status.
Cleanup restores gain before resetting the device. All of this uses volatile
RAM and registers; no vendor RAM firmware, ROM patch, flash or eFuse write is
part of the receiver.

Implementation: [mt7921_boot.c](../src/chips/mt7921_boot.c) and
[iq_stream.S](../firmware/iq_stream.S).

## Receiving through RF/PHY chain 0

The analog receiver selects the radio-frequency input, mixes it to baseband,
filters it and sets its gain. The digital physical-layer path supplies the
complex stream selected by the capture tap. The complete internal filter and
processing arrangement upstream of that tap remains incompletely mapped.

The host accesses analog registers through an RF SPI bridge. Physical SPI
port 1 is logical receive chain 0; port 0 is the companion bank, and port 5
is TOP, the shared analog control bank. The companion receiver can be idle
while its secondary synthesizer still supplies the active receiver's local
oscillator. Selecting a capture chain is therefore different from switching
an antenna connector.

### Clocks and tuning

The clock sequence establishes analog references, switches the digital mux,
and finishes the wake sequence before tuning. When the board strap selects
it, the sequence temporarily sets TOP `0xb00[16]`; wake must clear it and
wait before proceeding. Leaving this bit set suppressed external signals
while the capture and USB transport continued to operate.

The board has a 40 MHz crystal, while this synthesizer profile uses a 60 MHz
reference. The voltage-controlled oscillator runs at twice the requested RF
frequency, then divides by two. The driver calculates an integer divider and
a rounded 18-bit fraction, places the fraction in bits `[19:2]`, and writes
the tuning word with LOAD set. For channel 6, the selected secondary word
settles to `0x0513bbbc` after LOAD clears.

The tuning procedure also runs VCO calibration, waits for its completion flag
and latches the measured range code. That flag establishes completion, not
absolute frequency accuracy or a qualified PLL-lock indication. The final
routing uses distinct active and companion receive-enable values; copying
the active value to both banks weakened reception.

### Filtering and gain

The current analog bandwidth selector is zero, the existing 20 MHz profile.
The complex sample rate still gives a 40 MHz sampled span, with analog rolloff
within it. A separate selector trial changed the rolloff without changing the
capture rate, but wider filter calibration is not implemented in this backend.

Manual gain coordinates an analog override with several digital PHY fields.
The public codes are LNA 0–3, filter-stage gain 0–8 and digital gain 0–12;
these are not calibrated RF dB. The driver saves an unforced baseline,
clamps the analog gain first, applies the PHY settings and checks readback.
Restoration releases the analog clamp last and must happen before reset,
because the overrides can survive a Wi-Fi subsystem reset.

Released mode leaves the baseline unforced. It does not establish complete
AGC behavior, and the combined manual recipe does not prove that every
internal gain loop is frozen. Full AGC control, antenna routing and user
calibration coefficients remain unimplemented.

Implementation: [mt7921_rf.c](../src/chips/mt7921_rf.c) and
[mt7921_gain.c](../src/chips/mt7921_gain.c).

## Capturing with ICAP

The internal capture engine selects a digital tap and writes samples to SRAM
without a CPU sample-copy loop. Its configuration is separate from RF tuning:
a running producer pointer proves capture activity, not reception of the
intended signal.

The source-mode register at `0x830ad440` uses low-byte mode `0x13`. This selects
the dense single-chain layout that removes inactive-chain slots. The mux at
`0x830ad448` selects tap 4 for chain 0, enables bit 23 and sets divider bits
`[19:18]` to 3. The programmed low 28 bits are `0x008c0400`, the current
40 MSps profile. Research identified tap 5 with chain 1; that does not make
a second receiver available through the current API.

The host also enables receive/capture clocks, installs the SRAM bounds and
clears the extra packing field. The clock and upstream source changes were
qualified together; the independent purpose of every enable is not known.
The host leaves control at `0x4f1`, and the MCU writes `0x24f3` only after GO
to start circular capture. At the end, the MCU drains DMA before writing
`0x4f0` to stop the capture path.

The selected mode writes four consecutive complex pairs per 16-byte beat.
It does not require firmware compaction or 8-bit conversion. Changing the
mode or packing fields requires rechecking sample order, stride and producer
units; the existing decoder deliberately accepts only the known layout.

Implementation: [mt7921_capture.c](../src/chips/mt7921_capture.c).

## Buffering in circular SRAM

The capture memory occupies `0xe0200000` through `0xe023ffff`, a 256 KiB
ring containing 65,536 four-byte complex samples. The producer's low 16 bits
count sample address units modulo 65,536. These units are not bytes: the
corresponding byte offset is the sample position multiplied by four.

The byte layout of one beat is:

```text
Q[n], I[n], Q[n+1], I[n+1], Q[n+2], I[n+2], Q[n+3], I[n+3]
```

Each entry is a little-endian 16-bit word containing a 14-bit two's-complement
component; its upper two bits are zero. Negative components acquire their
16-bit sign extension on the host. There is no padding between complex pairs.

The ring holds only 1.6384 ms at 40 MSps. The MCU polls the producer while
waiting for samples and while waiting for DMA. It accumulates modulo-65,536
increments into a 32-bit produced count. Completed packets, rather than merely
submitted packets, advance the consumed count because DMA still needs the
source bytes until completion.

The producer guard fails a run when its poll interval reaches 750 microseconds
or its unread backlog reaches 61,440 samples. These are conservative firmware
limits for this profile, not independent hardware capabilities. A long poll
gap could hide a complete wrap; excessive backlog risks overwrite. Increasing
host buffers cannot recover overwritten SRAM.

Implementation: the `observe_source`, `wait_source` and `wait_space` paths in
[iq_stream.S](../firmware/iq_stream.S).

## Exporting through device DMA

The MCU submits descriptors to its TX0 DMA engine. In this context, TX means
sending bytes toward the USB host, not transmitting RF. This engine at
`0x5400xxxx` is separate from the host-interface scheduler at `0x7c024xxx`.

The program allocates four 16-byte descriptors in data memory at `0x02040000`
and four 64-byte header slots at `0x02040100`. Each I/Q descriptor joins two
memory regions: a 44-byte header and an 8,192-byte SRAM payload followed by
four trailer bytes. The payload address is
`0xe0200000 + (packet_sequence & 31) * 8192`, so successive packets walk the
ring in 2,048-sample chunks.

The descriptor written by this program is:

| Descriptor byte offset | Value | Meaning |
| --- | --- | --- |
| `+0` | Header-slot address | First segment in MCU data memory |
| `+4` | `(44 << 16) \| (1 << 14) \| 8196` | First length 44; second length 8,196; second segment is last |
| `+8` | Current SRAM payload address | Second segment, including the discarded trailer |
| `+12` | `0` | No additional metadata supplied by this producer |

The program publishes descriptor contents with a memory barrier, then advances
the CPU index. The hardware DMA index reports completion. Although the ring
has four entries, the I/Q path waits for each descriptor to complete before
submitting the next. Multiple outstanding SRAM descriptors previously produced
payload corruption even with clean sequence and error counters; serial
submission is an intentional constraint of the working path.

The trailer can contain a neighboring SRAM word, including the mapped word
just beyond the ring for its final chunk. It is transport framing, never an
extra sample. The firmware does not copy, scale or reorder the sample payload.
Changing the ring size, chunk size or trailer convention requires coordinated
changes in the assembly, capture setup and host parser.

Implementation: [iq_stream.S](../firmware/iq_stream.S), especially the descriptor
publication and drain paths.

## Transferring over USB

The library claims the vendor interface identified by class/subclass/protocol
`ff/ff/ff`. Endpoint roles follow descriptor order: the first bulk IN carries
events and I/Q, the first bulk OUT carries ROM commands, and the second bulk
OUT carries the firmware download. The interface number is discovered rather
than assumed. Register and mailbox accesses use the separate control endpoint.

The device aggregates events using the current 32 KiB size setting, timeout
code 100 and packet-limit code 30. These settings change USB transfer grouping,
not the sample format or sample rate. One I/Q event is 8,240 bytes: 44 header
bytes, 8,192 payload bytes and four trailer bytes. Payload throughput at
40 MSps is 160 MB/s; event framing increases it to about 160.94 MB/s before
USB protocol overhead.

The native reader defaults to 64 queued 64 KiB transfers. Its event thread
copies completed transfers into a bounded queue and promptly resubmits them;
the read caller consumes that queue and invokes application callbacks. Host
USB concurrency is independent of the single outstanding device descriptor.
A USB completion can contain part of an event or several events, so transfer
boundaries cannot be used as sample-packet boundaries.

The ROM continues servicing control requests while the original program runs.
The implemented live command is STOP through its mailbox. Gain and tuning
remain staged between reads; frequent control polling would also compete
with the data endpoint. Cleanup cancels and drains host transfers before
freeing buffers or resetting the dongle.

Implementation: [usb.c](../src/usb.c), [usb_stream.c](../src/usb_stream.c) and
[mt7921_boot.c](../src/chips/mt7921_boot.c).

## Decoding host I/Q

The host reconstructs events across arbitrary USB fragments, then checks their
length, type, sequence and boot nonce. It accepts at most one leftover ROM
start acknowledgment. It rejects gaps, repeats and invalid frames without
scanning ahead for another plausible header, because that would hide loss.

The sample decoder first checks every component's spare bits, then sign-extends
bit 13 and swaps wire-order Q,I into native-endian `int16_t` I,Q. The C API
preserves values in the range −8192…8191 without normalization, averaging,
decimation, equalization or an additional digital downconverter. The separate
CyberEther Python graph converts to CF32 and divides by 8192.

The event layout consumed by the parser is:

| Event byte offset | Size | Meaning |
| --- | --- | --- |
| `0` | 4 bytes | Packet class 7 in bits `[31:27]`; length 8,236 in `[15:0]`, excluding the trailer |
| `24` | 4 bytes | Event word `0x38000014 + 8192` |
| `28` | 1 byte | Event ID `0xed` |
| `32` | 1 byte | Extended event ID `0xf5` |
| `36` | 4 bytes | Packet sequence, starting at zero and wrapping at 32 bits |
| `40` | 4 bytes | This boot's nonce |
| `44` | 8,192 bytes | Raw Q,I payload: 2,048 complex samples |
| `8236` | 4 bytes | Discarded USB trailer |

The multi-byte fields are little-endian. The library batches converted samples
into application callbacks, by default 16,384 complex samples at a time;
callback size does not change the device's 2,048-sample packet size. On exit,
the parser must have no partial event, and host packet totals must match the
firmware's submitted/completed counts with no DMA errors. Earlier callbacks
may already have delivered a prefix when a later error invalidates the run.

Implementation: [mt7921_frame.c](../src/chips/mt7921_frame.c) and
[stream.c](../src/stream.c). Extension and test guidance is in
[architecture.md](architecture.md).

## Register reference

The tables summarize the implemented path and useful research findings, not a
complete register manual. The access column matters: equal numeric addresses
in different banks are not the same register. The known setting column records
only the fields we use or have identified; it is not an instruction to replace
an entire register. Preserve unrelated bits and the source's write ordering.

The access names map to [usb.c](../src/usb.c):

| Access name | Read type/request | Write type/request | Meaning |
| --- | --- | --- | --- |
| MMIO | `0xdf / 0x63` | `0x5f / 0x66` | Digital registers and mapped device memory |
| UHW | `0xde / 0x01` | `0x5e / 0x02` | USB host-wrapper path, including reset |
| Bridge | `0xc0 / 0x63` | `0x40 / 0x66` | RF SPI controller registers |
| RF port 0/1; TOP port 5 | Through Bridge | Through Bridge | Analog register offsets, not direct host MMIO |

The direct requests transfer a four-byte little-endian value, with address
bits `[31:16]` in `wValue` and `[15:0]` in `wIndex`. The analog helper encodes
the physical port in command bits `[15:13]`, the read flag in bit 12 and an
aligned register offset in `[11:0]`, then writes DATA to launch the transaction.
